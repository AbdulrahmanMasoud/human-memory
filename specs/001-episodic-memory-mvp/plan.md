# Implementation Plan: Episodic Memory Store with ACT-R Temporal Decay

**Branch**: `001-episodic-memory-mvp` | **Date**: 2026-03-28 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `specs/001-episodic-memory-mvp/spec.md`

## Summary

Build the MVP episodic memory system: a FastAPI service that stores text memories with semantic embeddings in Qdrant, metadata in PostgreSQL, and uses ACT-R base-level activation (power-law decay over access history) to rank retrieval results. A Celery background task recalculates activation every 30 minutes, marking under-threshold memories as decayed.

## Technical Context

**Language/Version**: Python 3.12+ (runtime: 3.13 in Docker)
**Primary Dependencies**: FastAPI, SQLAlchemy (async), Qdrant Client, Celery, ONNX Runtime
**Storage**: PostgreSQL 17 (metadata + access history), Qdrant (vectors + payloads)
**Testing**: pytest + pytest-asyncio + httpx (async test client)
**Target Platform**: Linux (Alpine Docker container)
**Project Type**: Web service (REST API)
**Performance Goals**: Retrieval < 100ms p95, Storage < 50ms p95
**Constraints**: Alpine Docker images, ONNX Runtime (no PyTorch)
**Scale/Scope**: Single-node, thousands of memories

## Data Model

### PostgreSQL Schema

**Table: `memory_metadata`**

| Column | Type | Default | Notes |
|--------|------|---------|-------|
| memory_id | UUID | gen_random_uuid() | Primary key |
| memory_type | VARCHAR(20) | 'episodic' | Memory classification |
| content | TEXT | NOT NULL | Original text content |
| created_at | TIMESTAMPTZ | NOW() | Creation timestamp |
| last_accessed | TIMESTAMPTZ | NOW() | Last retrieval time |
| access_count | INTEGER | 1 | Total access count |
| activation | FLOAT | 1.0 | Current ACT-R activation |
| salience | FLOAT | 0.5 | Emotional salience (V3) |
| emotion_valence | FLOAT | 0.0 | Valence score (V3) |
| emotion_arousal | FLOAT | 0.3 | Arousal score (V3) |
| decay_rate | FLOAT | 0.5 | ACT-R d parameter |
| status | VARCHAR(20) | 'active' | active / decayed / deleted |

Indexes: `(activation WHERE status='active')`, `(last_accessed)`, `(status)`

**Table: `access_history`**

| Column | Type | Notes |
|--------|------|-------|
| id | SERIAL | Primary key |
| memory_id | UUID FK | References memory_metadata |
| accessed_at | TIMESTAMPTZ | When the access occurred |
| context | TEXT | Optional context of access |

Index: `(memory_id, accessed_at DESC)`

### Qdrant Collection

**Collection: `episodic_memories`**
- Vector size: 384 (all-MiniLM-L6-v2 via ONNX)
- Distance: Cosine
- Payload fields: `content`, `memory_type`, `status`, `activation`, `timestamp`
- Payload indexes: `status` (keyword), `activation` (float)

### Request/Response Models

**POST /v1/memories** — Store
```
Request:  { content: str, memory_type?: str, context?: str }
Response: { memory_id: UUID, activation: float, created_at: datetime }
```

**POST /v1/memories/search** — Retrieve
```
Request:  { query: str, top_k?: int (default 7), min_activation?: float }
Response: { results: [{ memory_id, content, activation, similarity, last_accessed, access_count }], count: int }
```

**GET /v1/memories/{id}** — Recall
```
Response: { memory_id, content, activation, memory_type, created_at, last_accessed, access_count }
```

**GET /v1/memories/{id}/inspect** — Full Inspection
```
Response: { ...all metadata fields, access_history: [{ accessed_at, context }] }
```

**GET /v1/stats** — Statistics
```
Response: { total: int, active: int, decayed: int, deleted: int, avg_activation: float }
```

## Core Algorithm: ACT-R Retrieval Pipeline

```
1. Embed query text → 384-dim vector
2. Qdrant search(query_vector, limit=top_k*3, filter: status=active)
3. For each candidate:
   a. Fetch access_history from PostgreSQL (last 1000 entries)
   b. Compute B_i = ln(Σ t_j^(-0.5))  — base-level activation
   c. S_i = 0  (V1: no spreading activation)
   d. P_i = 0  (V1: no partial matching)
   e. ε = gaussian(0, 0.25)  — stochastic noise
   f. A_i = B_i + S_i + P_i + ε
4. Filter: keep only where A_i > τ (-1.0)
5. Sort by A_i descending
6. Take top_k results
7. Record access event for each returned memory
8. Return results
```
